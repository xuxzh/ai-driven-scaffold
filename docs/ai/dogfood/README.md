# Dogfood 记录规范

本目录记录 AI 治理流程在真实、小范围任务中的执行证据，用于识别流程摩擦与规则歧义。记录只提供事实与改进建议，不直接修改治理规则。

## 必填字段

每个任务必须记录：

1. **任务**：目标、范围与锚点文件。
2. **等级判定**：`L0` / `L1` / `L2` / `L3`，以及对应 `task-levels` 矩阵的判定依据。
3. **实际耗时**：开始时间、结束时间和墙钟耗时；不得用估算值代替。
4. **交付物**：实际新增或修改的仓库路径。
5. **运行命令**：命令、实际退出码与关键输出；不得用预期结果代替实际结果。
6. **失败 / 绕过**：失败步骤、重试、降级、未跑项及原因；没有时明确写“无”。
7. **规则歧义**：现行规则之间或规则与实际执行之间的不一致；没有时明确写“无”。
8. **建议**：基于事实提出的改进方向，并说明适用范围。

## 记录模板

```md
## <任务名称>

- 任务：
- 等级判定：
- 实际耗时：开始 <ISO 8601>；结束 <ISO 8601>；墙钟 <时长>
- 交付物：
- 失败 / 绕过：
- 规则歧义：
- 建议：

### 运行命令

| 命令 | 退出码 | 关键输出 |
|---|---:|---|
| `<command>` | `<code>` | `<actual output summary>` |
```

## 敏感信息边界

禁止记录以下内容：

- token、密码或 API key；
- `.env` 文件内容；
- 内部凭据、认证头、私钥或可复用会话信息。

命令输出若包含敏感信息，必须先脱敏，只保留验证结论所需的最小片段。无法安全脱敏时，记录“因敏感信息未附原文”及退出码，不复制原始内容。

## 规则变更边界

Dogfood 报告只提出建议，不自动成为硬门禁。任何新硬门禁必须另开 spec 与 plan，并按 `L3` 流程取得明确批准后实施。
